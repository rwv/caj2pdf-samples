# Recovered Archive.org `360-temp` samples

A retry of previously unavailable metadata exposed nine CAJ-named originals
in [the public item](https://archive.org/details/360-temp). Six canonical file
requests eventually succeeded; three returned HTTP 500. A bounded retry
through the public storage server supplied by Archive's own metadata acquired
all nine. Original byte sizes, SHA-1 and MD5 match; local SHA-256 deduplication
identifies **five new samples and four already catalogued originals**.
The [receipt](archive-360-temp-20261009.json) retains both attempts, identities,
checksums and the unchanged source/output evidence. No authentication or
restriction bypass was used. This does not imply redistribution permission.

The new originals are one actual CAJ (45 pages, 19 outline entries) and four
PDFs (19 pages total). All nine transfers convert through native CLI, Node and
real Chromium with identical output bytes; qpdf accepts all outputs without
warnings. Browser OPFS inventories are empty after every case. The complete
114 downloaded pages match in boxes, rotations, word positions and 72-dpi
MuPDF pixels. Only the 64 pages belonging to new identities increase the
catalog's accepted-page total.

For the eight PDFs, comparison uses the unchanged original. For the CAJ,
independent original-source inventory preserves all 248 objects and 110 raw
streams, allowing only eight proven Parent insertions and 22 generated
navigation objects. The original page table and GB18030 outline records
independently establish all 45 page identities/order and 19 titles,
destinations and levels. Every Page explicitly owns its geometry and Resources,
so a source-only reference can arrange those original pages by the source
table without inventing inherited geometry or consulting converter output.
All 45 reconstructed-source reference pages agree with the product.

Additional byte accounting covers the entire measured original PDF-object
body `[8916, 952195)`: no duplicate, omitted, opaque metadata stream or
unexplained body byte remains. The first attempt assumed the body ended at
file EOF and refused a separate container suffix. Independent bounded
inspection identifies 200 bytes of `FileProperty-Package` XML followed by
five padding bytes. A byte-identical diagnostic prefix verifies the PDF body;
the original remains unchanged. Only metadata structure/extents/hashes are
reported, with no XML leaf values or contact to embedded targets. These are
source-preservation proofs, not a proprietary vendor-viewer oracle.

Rust reviewed revision `f75b9e4605593ca8c7300a025af0f5db78750d82` and merged
revision `02adcc63eea447f82167facf0a38c0d2bb964684` have identical trees. This
batch needs no further converter change. Acquisition is independent of the
[SSE Extends repair](public-sse-collection-20261009.md).

After that separate catalog update, only five new rows are appended. All
1,386 existing rows remain unchanged; the four duplicate downloads appear in
the receipt without adding identities or page totals. The resulting catalog
has **1,391 identities: 1,346 conversion PASS, 18 FAIL and 27 UNSUPPORTED**.
The previous reconciled 36,494 accepted pages plus 64 new pages yields 36,558;
this is not a new full-catalog run. Other TTKN profiles, TEB/CAA, damaged-input
questions and broader fidelity work remain open. No skipped corpus test is
counted as a compatibility pass, and no release or irrecoverability claim is
made.
